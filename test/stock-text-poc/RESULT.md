# 종목 임베딩 텍스트 규격 비교 실험 결과 (WP-43)

- 실행일: 2026-09-08
- 스크립트: `stock_text_experiment.py`
- 환경: Python 3.11.16 (uv)
- 임베딩: `text-embedding-3-small` (프로젝트 GATEWAY)
- 종목·클러스터·정답: `test/issue-text-poc`와 동일한 32종목 + 3클러스터 (비교 기준을 맞추려고 재사용)
- 이슈 쪽 텍스트는 WP-42 확정 규칙(§6.2, D 방식)을 그대로 사용
- 소모 크레딧: 6 

## 비교한 방식

| | 만드는 법 |
| --- | --- |
| A | yfinance `longBusinessSummary` 그대로 (지금까지 실측에 쓰던 방식) |
| B | `{회사명}. {섹터} — {산업}. ` 접두 + 사업 설명 |
| C | B에서 상투 문구("~ was founded in ...", "~ is headquartered in ...") 제거 |

## 결론 — B 채택 (메타 접두, 상투 문구는 그대로 둔다)

세 방식 다 차이가 작다(순위 ±0.8, 분리도 ±0.006). **B가 어느 클러스터에서도 A보다 나쁜 적이 없고, Hormuz에서 Top-10 정답이 6개→7개로 늘었다.** 회사명·섹터·산업을 앞에 붙이는 게 손해는 없고 한 군데서 이득이라 B를 택한다.

**C(상투 문구 제거)는 이득이 없다.** Milton에서는 오히려 순위가 밀렸다(10.2 → 11.0, Top-5 3개 → 2개). 상투 문구가 32종목 전부에 거의 같은 형태로 들어 있어서 코사인 유사도에 대체로 대칭적으로 작용한다고 보인다 — 지우려고 정규식을 유지보수할 이유가 없다.

## 확정 규칙

```
종목 임베딩 텍스트 = {회사명}. {섹터} — {산업}. {yfinance longBusinessSummary}
```

- 전체 상한 2,000자 (넘으면 뒤를 자른다). 표본 평균 길이가 1,399자라 대부분 안 걸린다
- 설명이 비어 있으면 임베딩하지 않고 화면에서 제외한다. 회사명만으로 임베딩하지 않는다 — 이름만으로는 사업 정체성이 안 담겨 노이즈에 가깝다
- 상투 문구는 제거하지 않는다

## 함께 확인된 것

- 표본 32/32종목 모두 `longBusinessSummary`를 보유했다. 200종목 표본(2026-09-04, 명세 §4)의 100% 보유율과 일치한다.
- 상투 문구("~ was founded in...", "~ is headquartered in...")는 32/32종목 전부에 있었다 — yfinance 사업 설명의 사실상 고정 포맷이다.

## 한계

- 종목·클러스터·정답이 `test/issue-text-poc`와 같은 32개/3개 표본이다. 규모를 키운 재확인은 WP-34(종목 설명 수집·적재) 착수 시 200종목 표본으로 한다.
- 길이 상한(2,000자)에 걸리는 실제 사례가 표본에 없어 절단 방식(앞부분 우선 vs 문장 단위)의 영향은 이번에 재지 않았다.
