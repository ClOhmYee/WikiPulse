## 결론 — D 채택

**네 방식의 랭킹 품질 차이가 거의 없다.** 그래서 품질이 아니라 비용과 실패 위험으로 갈랐다.

- **D는 어느 클러스터에서도 최하가 아니다.** 문서가 여러 개면 B와 같고(4문서에서는 계산이 동일), 문서가 하나면 A와 같은 수준으로 붙는다(순위 4.0 동일). B는 단일 문서에서 2문장으로 잘려 A보다 나빴다(5.0).
- **A는 "대표 문서"를 고르는 규칙이 또 필요하다.** 클러스터에서 어느 문서가 대표인지 정하는 기준이 없고, 그 기준이 결과를 바꾼다. D는 그 선택 자체가 없다.
- **C(LLM 요약)는 이득 없이 비용만 든다.** 호출 1회와 4~6초가 추가되는데 품질은 동률이거나 낮다.

### C를 기각한 결정적 이유 — 실패 모드 셋을 실제로 봤다

1. **언어 불일치**: 1차 실행에서 프롬프트를 한국어로 쓰자 요약도 한국어로 나왔고, 종목 설명은 영어라 코사인이 절반으로 떨어졌다 (정답 평균 0.160 → 0.081). 프롬프트 한 줄로 파이프라인 품질이 반토막 나는 구조다.
2. **거부 응답이 그대로 입력됨**: 단일 문서(Nvidia) 클러스터에서 LLM이 "제공된 정보만으로는 사건을 설명할 수 없다"고 답했고, 그 문장이 그대로 임베딩 입력이 됐다.
3. **환각**: 1차 실행에서 Nvidia 클러스터에 대해 "미국 정부가 반도체 수출 규제를 강화했다"는, 입력에 없는 사건을 지어냈다.

셋 다 조용히 틀리는 유형이다. 에러가 나지 않아서 눈에 안 띈다.

## 확정 규칙

```
이슈 대표 텍스트 = 클러스터 문서를 다음 형식으로 이어붙인 것

  {문서 제목}: {도입부 앞 N문장}
  {문서 제목}: {도입부 앞 N문장}
  ...

N = 문서 1개면 6, 2~3개면 4, 4개 이상이면 2
전체 상한 2,000자 (넘으면 뒤를 자른다)
문서 순서는 급등도(pulse_score) 내림차순
출처는 Wikipedia API `prop=extracts&exintro&explaintext`, 리다이렉트 따라감
```

- **텍스트는 영어로 유지한다.** 종목 설명이 영어라 언어를 섞으면 유사도가 무너진다. 사용자에게 보여줄 한국어 문장은 LLM 검증 단계(WP-45)에서 따로 만든다.
- LLM 요약은 쓰지 않는다.

## 함께 확인된 것

- **절대 코사인이 낮다.** 사건형 클러스터의 분리도는 +0.05 ~ +0.15, 기업형은 +0.26이다. 사건 서술과 사업 설명은 같은 종류의 글이 아니라서, 임베딩만으로는 사건형 이슈에서 정답과 노이즈가 잘 안 갈린다. 명세 §6이 "뉴스 동시 출현이 주력, 임베딩은 보충"이라고 정한 것과 일치한다.
- Milton에서 노이즈인 Monster Beverage(MNST)가 세 방식 모두에서 상위권에 올라왔다. 임베딩 단독 후보에 노이즈가 섞이는 기존 관찰이 재현됐다.
- 방식 A는 Milton에서 2,000자 상한에 걸려 잘렸다. 상한값 자체의 영향은 이번에 재지 않았다.
