# 매칭 정답셋 (WP-39)

이슈-종목 매칭이 잘 되는지 잴 정답 사례 5건(사건형 3 + 기업형 2)과 채점 스크립트다.
정답 목록·사유·근거 기사는 [cases.py](cases.py), 결과와 결론은 [RESULT.md](RESULT.md).

프로덕션 코드가 아니라 근거 재현용이다.

## 실행

```bash
py -3 goldset_experiment.py result.txt 5,10
```

두 번째 인자는 등급 판정에 쓸 K 목록(쉼표 구분)이다. 바꿔서 다시 돌리면 그 K로 재채점한다.

`LLM_GATEWAY_KEY` 환경변수가 필요하다 (LLM 게이트웨이 키). 저장소에 넣지 않는다.

## 주의

- 출력은 UTF-8 파일로 쓴다. Windows 콘솔로 바로 뿌리면(`print`) 한글·em dash가 깨진다 —
  실제로 한 번 이 실수로 재시도 스크립트가 죽었다(2026-09-10).
- GDELT DOC API는 초당 요청 제한이 있다. 티커마다 따로 조회하면(57회) 20초 간격을 둬도
  429가 계속 났다 — 사례당 1회 ArtList(최대 250건 제목)로 묶어 5회로 줄였다. 그래도 가끔
  막히면 재시도 횟수가 아니라 **경과 시간**이 관건이다(스크립트가 90초 대기 후 1회
  자동 재시도한다).
- ArtList는 기사 **제목**만 준다. "회사가 곧 사건 당사자"인 경우(CrowdStrike·IBM)는 신호가
  잡히지만 "사건이 있고 회사는 2차 영향"인 경우(Milton·2023 은행위기)는 제목에 회사명이
  거의 안 나와 신호가 0에 가깝다 — 근거와 대응은 RESULT.md "GDELT 조회 방식과 그 실패" 절.
  실제 파이프라인(-48)은 title 그렙이 아니라 GDELT GKG 기관명 추출을 쓴다.
