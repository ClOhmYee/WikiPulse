# 비-seed 클러스터 멤버 — 편집 재급증 비율 실측 (WP-77)

기존 문서가 사건으로 재조명될 때(예: `Mojtaba_Khamenei`) 클러스터에 비-seed로
포함시킬 기준을 정한다. 예비 표본(2026-09-09, 4건)을 22건으로 늘리고 계절성
오염 처리(전년 동기 대조)까지 했다.

결과·결론: [RESULT.md](RESULT.md). 프로덕션 코드 아님 — 근거 재현용.

## 실행

```bash
py -3 measure.py
```

네트워크만 필요(Wikimedia REST 편집 통계 API), 인증 불필요. 문서당 호출 3회
(사건기간·직전기준·전년동기) — 22건 표본 기준 총 66회, 수십 초.

## ⚠️ 진행 중 발견한 함정

**"2026 Iran war" 사건 시각을 처음에 잘못 짚었다.** 명세 §11의 "Clickstream
2026-08" 언급만 보고 사건기간을 2026-08-01~08-16으로 잡았더니 `Mojtaba_Khamenei`
재급증 비율이 0.7배(신호 없음)로 나왔다 — 예비 표본의 17.9배와 전혀 다른 값.

원인 확인: 월별 편집 수를 직접 찍어보니(all-editor-types) **2026-03에 1,155건**,
8월엔 12건뿐이었다. "Clickstream 2026-08"은 그 사건의 클릭 트래픽이 늦게까지
남은 시점이지 편집 폭증 시점이 아니었다. 일별로 다시 보니 정점은 03-08(342건).
2026-03-01~03-16으로 고치자 재급증 비율이 **19.5배**로 예비 표본(17.9배)과
거의 일치했다 — 표본만 보고(문서 한 줄) 사건 시각을 단정하면 안 된다는 걸
이번에도 확인.
