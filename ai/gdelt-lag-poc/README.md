# GDELT 신호 지연 실측 (WP-46)

이슈 발생 직후 GDELT 동시출현(§6.3 b) 경로가 언제부터 쓸 만해지는지 실측한다.
사건 3건(자연재해형 2 + 단일 기업형 1)의 발생 시각부터 15분 단위로 GKG 슬롯을
받아, 이슈 매칭 기사 수·목표 기관 lift 가 시간에 따라 어떻게 쌓이는지 본다.

결과·결론: [RESULT.md](RESULT.md). 프로덕션 코드 아님 — 근거 재현용.

## 실행

```bash
py -3 measure.py
```

네트워크만 필요(무료 GDELT 엔드포인트), LLM_GATEWAY_KEY 불필요. 사건당 17슬롯(발생~+4시간)
다운로드 — 총 51개 파일, 수 분 소요.

## 방법

`gkg/parse.py`로 슬롯마다 기사를 파싱해 (a) 이슈 술어 매칭 여부 (b) 목표 기관
언급 여부를 센다. 발생 시각부터 누적으로 `lift`를 슬롯마다 다시 계산해 값이
언제 안정되는지 본다(+4시간 시점 값을 기준으로 ±20% 안에 처음 들어온 시점).

이슈 술어는 사건 유형별로 다르다:
- Milton(자연재해형): 명세 §11과 같은 테마+지역(`HURRICANE`+`florida`)
- CrowdStrike·SVB(기업형): 씨드 기관명 자체를 술어로 씀(`org:` 접두)
