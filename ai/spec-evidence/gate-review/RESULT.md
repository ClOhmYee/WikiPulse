## 7. 🔴 완전 제거의 진짜 비용 — `max_rev_id`

편집을 안 보면 `spike.max_rev_id`(그 윈도우 마지막 revision)가 안 생긴다. 그게 as-of 링크 앵커다.

```
cluster/driver.py:858     anchored = [s for s in seeds if s.max_rev_id is not None]
cluster/asof_links.py:14  🔴 max_rev_id 가 없으면 현재 판으로 폴백하지 않는다
```

앵커 없는 root 는 **CORE 에서 통째로 빠져 singleton** 이 된다. 2026-09-22 에
`CLUSTER_FETCH_LINKS` 로 만든 멀티 멤버 30건이 그대로 무너지고, replay 대표 텍스트 고정
(명세 v0.3 시점 정합성)도 같은 앵커를 쓴다.

→ 앵커를 **`snapshot_ts` 이하 최신 revision** 으로 바꾸면 편집이 없어도 항상 있다. 별도 작업이다.

## 9. 🔴 반증 — 모바일 문턱을 버리고 온 경로 (2026-09-22 저녁)

§5 는 사례 6개로 "겹치는 구간이 없다"고 했다. **내가 고른 6개였다.** 전수로 재보니
셋 다 틀렸다는 게 드러났다. 순서대로 적는다 — 다음에 같은 길을 다시 파지 않게.

### 9-1. 분포가 두 봉우리가 아니다

2026-09-21 15:00Z 한 시간, 조회수 100+ 문서 **8,189개**의 모바일 비중 (`whatenters.py`
와 같은 입력):

```
  0~ 5%      62  ###
  5~10%      21  #          ← 여기가 골짜기
 10~15%      25  #
 15~20%      28  #
 20~25%      44  ##
 25~30%      53  ##
 ...
 70~75%   1,102  ##################################################
```

**하나의 큰 덩어리에 얇은 왼쪽 꼬리다.** 0.25 는 골짜기가 아니라 올라가는 경사면이었다.

### 9-2. 낮은 모바일 = 봇이 아니다

| 구간 | 실제 내용 |
| --- | --- |
| 0~10% | `.xyz` · `Neatsville, Kentucky` · `Limonene` · `ISO 3166-1 alpha-2` — 기계 |
| 10~20% | `Google Search` · `List of HTTP status codes` · `Python (programming language)` |
| 20~25% | **`2026 Kohat attack`(1,809회)** · `The Hobbit` · `Black hole` |

🔴 10~20% 구간은 봇이 아니라 **업무 중 데스크톱으로 보는 주제**다. 두 가지를 상수
하나로 가르려 한 것이 오류이고, 그래서 0.25 는 실제 테러 사건 기사를 잘랐다.

### 9-3. "봇"이라 부른 것들은 급등한 적이 없다

자기 직전 28일 대비 배수 (`junk.py`):

| 문서 | 그날 | 평소 | 배수 |
| --- | --- | --- | --- |
| `Neatsville, Kentucky` | 102,848 | 89,234 | **1.2×** |
| `Limonene` | 62,978 | 59,526 | **1.1×** |
| `.xyz` | 257,104 | 87,218 | 2.9× |
| `Lizzie Borden` | 806,041 | 16,191 | 49.8× |
| `2026 Kohat attack` | 28,211 | 1,745 | 16.2× |

**상시 크롤러는 매일 9만 회씩 꾸준히 받을 뿐이다.** 기준선이 있으면 저절로 떨어진다 —
대리 지표가 애초에 필요 없었다. 운영 `page_baseline` 이 0행이라 그 자리가 비어 있었던
것이 진짜 문제이고, `WP-212` 로 분리했다.

### 9-4. "봇이 돌았으면 뭔가 있었던 것 아니냐" — 검증 가능했고 떨어졌다

가설: 크롤은 누가 시킨 것이니 그 이유가 사건일 수 있다. → **봇이 먼저 돌면 사람이
뒤따라야 한다.** 일별 데스크톱/모바일을 열흘 봤다.

```
Roblox   08-09     2,806 /  4,155
         08-10  4,777,498 /  3,746   ←봇. 모바일은 오히려 줄었다
         08-11     3,347 /  3,415
         ...08-20 까지 평소. 사람 급등이 끝내 안 온다

Lowe's   08-18    10,468 /    258   ←봇
         08-25     4,269 /    180   ←봇   ← 정확히 일주일 간격
```

🔴 **`Lowe's` 가 결정적이다 — 같은 요일 일주일 간격은 사건이 아니라 스케줄된 크롤 잡이다.**
크롤의 이유는 있지만 그 이유가 "화요일마다 이 페이지를 긁는다" 라면, **무엇에 대한
이슈인지도 언제인지도 말해주지 않아** 우리가 쓸 수 있는 정보가 아니다.

대부분 singleton 이라 아직 그 신호를 못 쓴다.

### 9-6. 그래도 §3(일회성 폭주)은 남는다

기준선을 채워도 `Roblox`(평소 7천 → 478만)는 배수로 통과한다. 빈도는 상장사 급등
174건 중 모바일 10% 미만이 **16건(9.2%)**, 일반 문서(2.2%)의 4배다 —
⚠️ **스크래퍼가 노리는 대상이 정확히 우리 대상(기업 문서)이기 때문이다.**
그때 볼 값은 문턱이 아니라 **그 문서 평소 대비 이탈**(Roblox 평소 60% → 0.1%)이고,
V15(`page_view_hourly.mobile_views`)가 그 데이터를 쌓기 시작했다.
