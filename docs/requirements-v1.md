## 1. 목적과 범위

WikiPulse는 영어 위키백과의 사람 편집과 문서 조회수 급증을 순서대로 확인해 이슈를 감지한다. 시점별 이슈를 펄스맵과 이슈 탐색 화면에 보여 주고, 미국 상장 종목 후보의 사업 관련성을 LLM으로 검증해 근거와 함께 제시한다. 종목 연결은 주가 방향·수익률의 예측이 아니다.

사용자 화면은 펄스맵(`/pulse`), 이슈 탐색(`/issues`), 이슈 상세(`/issues/{id}`), 종목 목록·상세(`/stocks`·`/stocks/{ticker}`), 로그인·내 정보·보관함(`/mypage`·`/saved`)으로 구성된다. 이슈 기록 화면은 API 모드와 `VITE_ISSUE_HISTORY_ENABLED=true`가 모두 충족될 때 사용한다. 알림, 토론, 문서 단독 상세, 통합 검색 API, 과거 유사 사례와 이슈 유형 자동 분류는 현재 구현 범위 밖이다.

## 2. 이슈 감지

1. `enwiki` namespace 0에서 봇이 아닌 편집 이벤트를 수집한다. 한 집계 창에 사람 편집이 1건 이상 있으면 조회수 검사 후보가 된다. 편집 z-score, 편집 10건, 편집자 2명은 관문이 아니다.
2. 최종 관문은 Wikimedia `other/pageviews` 시간별 덤프다. 기존 문서(생성 후 28일 이상)는 직전 28일 기준선 대비 `z >= 3`, 평소의 2배 이상, 시간별 조회수 100 이상을 모두 충족해야 한다. 생성 후 28일 미만 문서는 생성 이후 표본을 즉시 사용하고, 통계를 계산할 수 없거나 기준 조회수가 0이면 조회수 100 이상을 적용한다. AQS 일별 API는 운영 최종 관문에 사용하지 않는다.
3. 원본이 아직 오지 않았으면 `spike_candidate`에 보관하고 도착 후 재판정한다. 확정·폐기 시 후보를 지우며 36시간 이상 미도착한 후보는 만료한다. `spike`에는 최종 관문을 통과한 문서만 쓴다. 시간별 조회수와 맞물리는 정각 창에서만 확정한다. `page_view_hourly_ingest`는 조회수 0과 원본 미도착을 구별한다.
4. 문서 생성 시각은 시스템 최초 관측 시각(`first_seen`)과 구별해야 한다. 현재 기본 급증 판정 코드의 `is_new_page`는 실제 생성 후 28일 여부가 아니라 기준선 표본이 7일 미만인지 나타낸다. `wiki_page.page_created_at` 컬럼은 현행 DDL에 없다. 선택형 Clickstream 확장은 별도 `batch.page_creation` 인덱스로 historical 생성 시각을 읽는다. 따라서 위 신규 문서 28일 계약을 기본 급증 경로에서 완전히 구현했다고 표시하지 않는다.

시간별 덤프는 창 종료 기준 125~153분 뒤 도착한 기록이 있다. 목표는 사건 후 통상 2~3시간 안에 최종 노출, 원본 도착 후 내부 처리 15분 이내다. 이는 설계 목표이며 지속적인 운영 SLA 달성 실측으로 해석하지 않는다. `page_view_hourly.mobile_views`는 전체 조회수에 포함되는 부분집합이다. V16 이전 행의 0은 미측정일 수 있으므로 이를 근거로 봇 판정을 하지 않는다.

## 3. 클러스터와 시점

동일 시점의 `spike` 후보를 조회수 내림차순으로 최대 20개 고른다(동점은 `page_id` 오름차순). 같은 문서를 직전 24시간 안에 다시 루트로 고르지 않는다. 선택된 루트 간에는 해당 판정 시점 revision의 wikitext에 있는 직접 링크만 사용한다. `spike.max_rev_id`를 앵커로 삼고, 과거 revision이 없으면 현재 문서 링크로 대체하지 않는다. 한 방향 링크도 연결로 취급하며, connected component에 sym focus `τ=0.005`와 D2 directional bridge 억제를 적용한다. 각 component가 이슈 클러스터다.

Clickstream 이웃을 붙이는 확장 코드는 보존하지만 **기본 OFF**다. 켜지 않은 기본 클러스터의 멤버는 선택된 루트다. Clickstream 월별 이동량은 확장·화면 간선의 근거이지, 현재 기본 CORE 연결의 근거가 아니다. Wikidata 보조 간선은 데이터 모델에 있으나 생산 소스 배선은 확인되지 않았다. `cluster_snapshot`에는 이슈가 0개인 완료 시점도 기록한다.

과거 재생은 2026-07-17~09-17 구간을 대상으로 LIVE와 같은 판정 계약을 사용한다. 점수·멤버·편집수·조회수·기준선은 각 스냅샷에 고정한다. 요약·종목 후보·검증 결과를 같은 `issue_key`에 재사용할 때는 **원본 클러스터 `snapshot_ts <=` 대상 `snapshot_ts`**만 허용하고 가장 가까운 과거 원본을 선택한다. `generated_at`과 `verified_at`은 처리 시각이므로 이 사건 시점 상한 대신 쓰지 않는다. 같은 대표 문서의 LIVE/리플레이 이력 묶음은 탐색 편의를 위한 것이며 현실의 단일 사건임을 보증하지 않는다.

2026-09-22의 2개월 클러스터 분석(1,104 스냅샷·19,432 component)은 알고리즘 실측이다. 2026-09-23에는 조회수 산출물이 한 시간 밀린 사실이 발견되어 운영 리플레이를 재생성 중이라는 기록이 있다. 따라서 그 수치를 교정 후 운영 데이터의 최종 검증 완료로 간주하지 않는다.

## 4. 종목 연결과 리포트

SEC/NASDAQ 종목 마스터·사업 설명을 PostgreSQL에 저장하고 `text-embedding-3-small` 1536차원 벡터로 후보를 검색한다. 이슈 대표 텍스트와 종목 설명의 임베딩 상위 20개, GDELT GKG 기관 근거 상위 10개의 합집합을 만든다. 후보 우선순위는 `BOTH` → `GDELT_ONLY` → `EMBEDDING_ONLY`다. 3등급 생략 게이트는 `N=0`으로 꺼져 있어 모든 후보가 검증 대상이다. LLM은 사업 연관 경로와 근거 문장을 만들 수 있는지 판정한다. 통과 종목만 노출하며 제품 노출 개수 상한은 두지 않는다.

검증 기본 모델은 `gpt-5.4-nano`, 이슈 요약 기본 모델은 `claude-sonnet-4-5-20250929`다. 요약 writer와 상태 전이 코드는 구현돼 있으나 기본 워커 설정은 꺼져 있다. `CONFIRMED`는 요약과 종목 검증이 모두 완료된 상태이며 통과 종목 0개도 정상 완료 후에만 허용한다. 외부 호출 실패·미도착은 처리 중 또는 재시도로 남긴다. 섹션형 `report`는 저장된 경우에만 노출한다. 현재 생성 경로는 시연 이슈용 일회성 도구이며 자동 리포트 생성 워커는 없다.

주가 상세 API·프론트 차트와 이슈 시점 마커는 구현됐다. 2026-09-18 로컬 검증에서 시연 44종목의 일봉을 적재했으며 전 종목·전 기간의 실데이터 보유를 뜻하지 않는다. 일봉이 없는 기간은 빈 결과로 표시하고 보간하지 않는다.

## 5. 계정·보관함과 표현

이메일 가입·로그인·로그아웃, 내 정보, 이슈 북마크, 관심종목 보관함은 구현됐다. 인증은 HttpOnly 세션 쿠키, PostgreSQL Spring Session, CSRF 토큰을 사용한다. Bearer 토큰을 반환하거나 브라우저 저장소에 보관하지 않는다. 북마크는 이슈의 특정 `cluster_id`를 가리키며 새로운 스냅샷으로 자동 대체하지 않는다. 알림·댓글 API는 구현되지 않았다.

문서 식별·위키 링크는 영어 원문 `wiki_page.title`을 사용한다. 화면 표시명은 `title_ko`(ko.wikipedia 정식 제목) → `title_ko_fallback`(기계 번역) → `title` 순서다. 기계 번역은 위키 링크 주소가 아니다. 표시명 채우기 워커는 기본 OFF이며 번역 키가 없으면 영어 제목으로 표시한다.

## 6. 완료 판단과 현재 한계

코드·마이그레이션 존재, 로컬 통합 검증, 운영 배포, 운영 데이터 처리 완료를 각각 구분한다. 저장소에는 V1~V16·V20·V21 마이그레이션이 있지만, 확인한 운영 스키마 실측은 2026-09-22의 V14까지다. V15 이후 운영 적용은 이 문서만으로 보증하지 않는다. 신규 문서의 실제 생성일 기준 판정, 9월 23일 이후 리플레이 재실행 완료, 전체 GDELT lift 자동 집계, AI 워커 상시 활성화도 추가 구현·운영 확인이 필요하다.

제품의 핵심 수용 조건은 (1) 편집 후 조회수 최종 관문을 통과한 문서만 이슈로 노출, (2) 선택 시점의 고정된 지표·원문·근거만 표시, (3) 검증된 종목과 근거만 제시, (4) 미처리·원본 없음·정상 0건을 구별, (5) 로그인 사용자별 저장 상태를 분리하는 것이다.
