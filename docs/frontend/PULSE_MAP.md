# 펄스맵 시간 탐색과 문서 그래프

2026-09-21 갱신 · WP-37, 71~76, 93~98, 101, 112, 116, 122, 125, 153

## 구현 범위

Spring의 `IssueController`/`PulseMapService`에 스냅샷 목록과 지도 조회가 구현되어 있다. 프론트는 해당 DTO를 검증하고 같은 형식의 raw mock을 사용한다. 스냅샷 생산·저장 코드와 조회 코드가 존재하는 것과 실제 수집 → 탐지 → 저장 → API → 브라우저가 실행된 것은 구분한다. 이번 HTTP 가로채기 검사는 후자의 완료 증거가 아니다. 운영 source 배선 및 검증은 WP-94와 [API 협의 사항](API_DECISIONS.md)을 따른다.

`/pulse`와 `/issues`는 독립 페이지다. 지도/목록 전환은 삭제했다. 이슈 탐색 내부의 카드/리스트 버튼은 검색·필터·정렬·저장을 유지하며 기본은 리스트다. 이슈 주제는 정치·국제·사회·경제·기술·과학·문화·스포츠·환경·기타이며 종목 산업·섹터와 별개다.

## 시간과 선택

- 최초 진입에는 클러스터 정보 패널을 숨긴다. 일반·전체화면 모두 클러스터나 문서를 선택하면 열리고, 저장 버튼 오른쪽 닫기 버튼으로 선택을 해제하며 닫는다. 일반 모드에서 닫힌 패널의 빈 열은 남기지 않고 지도를 전체 너비로 표시한다.
- 일반·전체화면 전환과 화면 크기 변경 시 배율과 화면 중심에 보이던 지도 좌표를 유지한다. SVG를 실제 화면 중심 기준으로 그려 임시 viewBox와 비동기 크기 보정으로 인한 전환 중 배율 튐을 방지한다. 상세 모드의 클러스터·문서 선택 및 선택 해제는 배율과 지도 중심을 바꾸지 않으며, 필터·시점 변경 시에는 새 배치의 중심과 기본 배율로 돌아간다. 정보 패널 내부 스크롤 위치는 아직 모드 전환 시 유지하지 않는다.

- 날짜와 출처를 고르고, 슬라이더로 같은 출처의 전체 기간을 이동한다. 슬라이더 위치는 실제 시간 차이에 비례한다. 날짜 변경 시 해당 날짜의 마지막 시점, 최초 진입은 최신 LIVE(없으면 최신 replay)를 선택한다. 자동재생·자동 폴링은 없다. 최신 이동은 로드된 시점 목록 기준이다.
- 일반 모드 시간축도 선택 날짜·최신 이동·이전/다음·슬라이더만 남긴 간결한 배너로 표시한다. 데스크톱은 한 줄, 모바일은 두 줄이며 안내 문구·월별 눈금·기간 양끝 라벨은 생략한다. 슬라이더 간격은 실제 시간 차이에 비례하고 일반 모드 배너는 항상 표시된다.
- API 시각은 UTC `Z`, 화면 날짜·시각은 KST다. 날짜 목록은 제공된 범위의 빈 날짜를 비활성화한다. 완료된 빈 스냅샷과 아직 저장되지 않은 시점은 다르다.
- 지도·이슈 선택 목록·정보 패널에는 해당 시점의 모든 클러스터를 표시한다(WP-112). NEW는 `0 <= snapshotTs - firstDetectedAt < newWindowHours`이며 기본 24시간이다. 최초 감지 미제공은 NEW로 추정하지 않는다. API의 HOT 판정은 유지하되 펄스맵에는 HOT 배지를 표시하지 않는다. 클러스터가 없는 스냅샷은 빈 상태로 안내한다.
- 조회마다 AbortSignal을 전달하고 `useAsyncResource`의 요청 수명 검사로 이전 응답을 버린다. 대기 중 이전 지도·패널을 숨기고 새 응답을 함께 표시한다. 오류 시 재시도하며 mock으로 대체하지 않는다.
- 클러스터 `id`는 상세·저장용, `issueKey`는 시점 간 추적용이다. 같은 issueKey의 선택은 유지한다. DB의 issueKey가 null이면 source/시각/id로 화면용 키를 만들며 시점 간 연속성을 추정하지 않는다. label이 없으면 문서 제목 또는 "제목 미제공"을 표시한다. 표시 제목은 `label` → root/lead 문서 `titleKo` → 그 `title`(영문) → "제목 미제공" 순이며, 문서 하나의 표시 제목은 `titleKo` → `title`이다(WP-205). 🔴 `title`(영문)은 대체하지 않는다 — 위키백과 링크·클러스터링 키·내부 식별자가 그 값을 쓴다. 검색은 한국어·영문 제목을 모두 색인한다. 사라진 이슈·문서는 선택을 해제하고 안내한다. 검색·카테고리로 가린 선택은 지표를 다른 이슈로 바꾸지 않는다.

## 그래프와 지표

- 클러스터마다 `nodes`의 문서 하나를 노드 하나로 그린다. 같은 문서가 서로 다른 클러스터에 속하면 각 클러스터 안에 한 번씩 나타난다. 간선은 같은 클러스터의 `sourcePageId`와 `targetPageId`를 연결하며 membership weight에서 만들지 않는다.
- `sizeScore`는 지도 DTO의 공통 척도 0~1이다. 반지름은 `12 + 28 * sqrt(sizeScore)`로 확대하고 매 시점 최댓값으로 정규화하지 않는다. 미제공은 반지름 12의 점선 노드로 표시한다. 0과 null을 구분한다.
- 원시 `spikeScore`와 이슈 `pulseScore`에 배수 기호를 붙이지 않는다. WP-93에서 탐지 점수 축을 수정했지만 기존 저장 행의 재계산과 지도 `scoreVersion` 식별 규칙은 확인이 필요하다. 신규/기존 문서의 점수 축과 HOT 임계값의 의미를 버전별로 합의해야 한다([협의 사항](API_DECISIONS.md)).
- Clickstream은 실선·방향 화살표로 표시하고 관계 가중치는 해당 덤프의 이동량 `n`만 사용한다. 실시간 신호와 비율 혼합하지 않는다. 선택 스냅샷의 직전 월 검증 완료본이 우선이며, 미공개·검증 실패 시 가장 최근 완료 월(통상 전전월)을 유지한다. 서로 다른 월을 합산하지 않는다. Wikidata 점선은 이미 클러스터에 포함된 멤버 사이의 보조 근거를 표현하는 API·UI 계약만 남아 있고, 현재 데이터 소스 배선은 없어 실제 응답에 생성되지 않는다. 간선이 있으면 패널에 근거 명칭과 실제 사용한 Clickstream 기준 월 또는 Wikidata 관측 시각을 제공하며 순간 이동량으로 설명하지 않는다.
- 상세 모드의 클러스터 선택은 요약 표시, 문서 선택은 지표·연결 강조다. 선택에 따른 자동 확대·이동은 없다. 기존 정보 패널과 전체화면 정보 패널 모두 요약 아래의 **이슈 리포트 보기** 버튼으로 해당 클러스터 `id`의 `/issues/:issueId`에 이동한다. 원문은 별도 링크로 새 탭에서 연다. 확대·축소·드래그·중앙 초기화, 그래프 방향키 이동, Enter/Space, 슬라이더 방향키/Home/End를 지원한다.
- React SVG + d3-force 3.0.0을 사용한다. API 객체를 복사해 문서 배치를 100 tick 계산하고 issueKey/pageId별 상대 위치를 캐시한다. 클러스터는 현재 스냅샷의 `pulseScore` 내림차순(동점은 issueKey순)으로 가장 높은 것을 원점에 놓고, 중요도가 낮아질수록 더 먼 황금각 나선 방향에 놓는다. 외곽과 제목 공간을 포함해 충돌을 피한다. 검색·주제 필터를 적용하면 결과에 남은 클러스터만 점수순으로 다시 방사형 배치한다. 클러스터 내부 문서의 상대 위치와 노드 크기는 유지한다. 필터 변경 시 화면 중심을 새 배치의 중심에 맞추며, 전체로 되돌리면 전체 클러스터 기준 배치를 복원한다.
- 화면 크기로 뷰포트를 정하므로 클러스터가 많아도 전체를 화면에 맞춰 축소하지 않는다. 주변 클러스터는 드래그·방향키·축소 또는 이슈 목록 선택으로 탐색한다. 모바일도 같은 방사형 배치를 사용하고 일반 화면의 패널은 아래에 둔다.
- 전체화면 버튼은 창에서 16px(모바일 8px) 여백을 남긴 지도 전용 dialog를 연다. 선택 시 데스크톱은 오른쪽 360px 패널, 모바일은 오른쪽 오버레이를 표시한다. 패널 자체 닫기, 전체화면 닫기, Escape, 배경 스크롤 잠금과 포커스 복귀를 지원한다.
- 일반/전체화면 모두 지도 SVG 위의 휠 입력으로 포인터를 중심으로 확대·축소한다. 휠 이동량을 연속 배율로 변환하고 프레임별로 보간한다. 버튼은 1.2배씩 부드럽게 이동하며, 모션 감소 설정에서는 보간 없이 바로 반영한다. 드래그·초기화·선택 변경은 진행 중 확대 애니메이션을 취소한다.
- 확대 범위는 최소 `0.12 × 1.2⁴`(약 24.88%), 최대 `(4 / 1.4³) × 1.2²`(약 210%)다. 후속 요청으로 최소 17.28%에서 축소 두 단계를 더 제거했다. 클러스터 경계 사이 최소 여백은 지도 좌표 기준 120에서 240으로 늘렸다.
- 최초 진입과 지도 위치 초기화의 기본 배율은 100%에서 현재 축소 버튼 한 단계 낮춘 `1 / 1.2`(약 83%)다. 상세 모드의 클러스터 선택 시 현재 배율과 중심을 유지한다.
- 클러스터 제목은 기본 배율의 크기를 유지하면서 화면상 크기가 `(zoom / DEFAULT_ZOOM)^0.35`에 비례하도록 보정한다. 클러스터보다 완만하게 확대·축소되며 데스크톱 기준 약 12~21px 범위로 표시한다. 문서 제목은 상세 모드에서 노드 내부에 표시하며 노드 크기에 맞춰 글꼴을 제한한다. 긴 제목은 한두 줄 뒤 말줄임 처리하고 포커스·선택 시 전체 이름을 표시한다.
- 전체화면 시간축은 상단 자동 숨김 패널로 제공한다. 날짜·최신 이동·이전/다음·슬라이더를 데스크톱 한 줄, 모바일 두 줄로 압축하며, 지도 위에 겹쳐 표시해 지도 높이를 줄이지 않는다. 상단 영역에 마우스를 올리면 220ms 동안 내려오고, 벗어난 뒤 900ms가 지나면 위로 올라가며 숨는다. 다시 진입하거나 키보드로 조작하거나 슬라이더를 누르고 있는 동안은 닫히지 않는다. 터치는 상단 핸들로 열고 지도 영역을 누르면 잠시 뒤 숨는다. 모션 감소 설정에서는 이동 애니메이션을 생략한다.
- 전체화면 시간축 배너 안쪽 하단에는 전체·카테고리 선택 버튼을 한 줄로 배치한다. 좁은 화면에서는 가로로 스크롤하며, 일반 모드와 같은 필터 상태를 공유한다. 시간축과 함께 나타나고 숨으며 카테고리 조작 중에도 패널이 유지된다.
- 고정 상단 바는 없으며 화면 최상단의 투명한 감지 영역에 마우스를 올리면 시간축이 나타난다. 키보드로 영역에 포커스하거나 터치 기기의 상단 핸들을 누를 수도 있다. 클러스터 정보 닫기는 저장 버튼 바로 오른쪽에, 전체화면 종료는 지도 하단 확대·축소 컨트롤의 오른쪽 끝에 배치한다.
- 로딩·오류·빈 지도에서도 상단 시간축을 열 수 있고 우측 하단에 전체화면 닫기 버튼을 유지한다. 전체화면을 닫아도 선택 시점을 유지하며, 빈 지도에서 닫으면 일반 화면 시간축에 포커스를 돌려준다. 공간을 확보하기 위해 지도 위의 별도 데모 안내 문구는 제거했다.

## 네온 디자인과 원형 스캔 (WP-122)

색상·타이포그래피·모션 기준: [PulseMap 디자인 명세](../design/pulse-map/DESIGN.md).

- 선택한 NEON PULSE 시안의 짙은 네이비 배경, 주제별 네온 테두리와 절제된 발광을 일반·전체화면 지도에 적용한다. 청록·파랑·보라·마젠타에 경제의 앰버 `#ffc46b`, 과학의 라임 `#c4ed76`를 더해 구분한다. 주제별 색은 `neonTheme.js`에 고정하며 시점이나 필터에 따라 바뀌지 않는다. 시안의 예시 주제·노드 수·연결은 데이터로 사용하지 않는다.
- 지도 클릭·드래그 시 브라우저 기본 포커스 테두리는 숨긴다. 키보드로 지도에 진입하면 기존 `focus-visible` 테두리를 표시한다.
- 상세 모드의 클러스터 경계는 기본적으로 전체 점선이다. 마우스를 올린 클러스터에만 서로 반대편의 실선 호 두 개를 표시하며, 중심에서 마우스로 향하는 각도를 따라 회전한다. 노드 위에서도 유지하고 확대·이동된 클러스터의 로컬 좌표로 방향을 계산한다. 터치에서는 호를 표시하지 않으며 모션 감소 설정에서는 회전 없이 호만 표시한다.
- 원형 스캔은 **펄스맵 좌표 중심 `(0, 0)`**에서 시작한다. 지도와 동일한 카메라 변환을 받아 드래그·확대 시 중심과 파동이 함께 이동한다. 약 4초 주기 중 2.5초 동안 전체 지도 배치의 외곽까지 확장하고, 지나는 노드와 간선에는 해당 주제 색으로 최대 600ms 잔광을 준다. 통과 시점도 지도 좌표 거리로 계산한다. 데이터 조회나 갱신을 수행하지 않는 시각 효과다.
- 지도 하단의 일시정지/재생 버튼으로 스캔을 제어한다. 설정은 페이지 내 전체화면 전환·필터·시점 변경에도 유지한다. 시스템 `prefers-reduced-motion`이면 스캔을 끄고 버튼에 적용 상태를 안내한다. 지도가 화면 밖이거나 탭이 숨겨지면 프레임을 중단한다.
- 상세 모드에서는 모든 문서의 라벨을 노드 내부에 표시한다. 노드 반지름에 비례한 내부 사각 영역을 사용하고, 작은 노드는 한 줄·그 외에는 두 줄까지 표시한 뒤 넘치는 글자를 `…`로 줄인다. 공간·충돌·배율을 이유로 라벨을 생략하지 않는다. 문서에 마우스를 올리거나 키보드로 포커스하거나 선택하면 전체 이름을 별도 표시한다. 선택 패널과 접근성 이름도 원본 제목을 유지한다.
- 전체 이름 박스는 한 줄·여러 줄 모두 텍스트 블록을 세로 가운데에 맞춘다. 클러스터 제목에도 같은 네이비 배경과 주제색 테두리 박스를 씌우고, 제목 박스·여백·둥근 모서리는 글자와 같은 완만한 비율로 확대·축소한다.
- 클러스터 제목 박스는 우측 하단에 주제색 그라디언트와 은은한 빛번짐을 둔다. 스캔이 제목 박스 중심을 지나면 테두리·내부 빛·외부 글로우가 밝아지고 600ms 잔광으로 잦아든다. 확대·축소로 변하는 제목 위치를 스캔 좌표에 반영하며, 일시정지·모션 감소·화면 밖에서는 기본 빛번짐만 유지한다. 글자에는 블러를 적용하지 않는다.
- 발광은 재사용 SVG 그라디언트를 사용하고 프레임별 DOM 갱신은 약 30fps로 제한한다. 매 프레임 React 상태 갱신이나 데이터 요청을 추가하지 않는다. 선택 노드의 작은 그림자와 제목 박스 뒤의 제한된 블러를 사용하며, 스캔 중에는 블러 반경 대신 투명도를 변경한다.
- 검증: `e2e/pulse-neon.spec.js`에서 화면 좌표 기준 스캔/노드 일치, 일시정지·전체화면·모션 감소·화면 밖 중단, 지도 범위 axe 검사, 데스크톱/모바일 캡처를 확인한다. 기존 `pulse.spec.js`, `pulse-zoom.spec.js`와 API 모드 `e2e-api/pulse.spec.js`도 회귀 범위에 포함한다. API 모드 검사는 HTTP 응답 가로채기이며 실제 백엔드 연동 증거가 아니다.

## 확대·축소 렌더링 (WP-125)

- `useMapCamera`는 보간 중 현재 카메라를 ref와 구독자에 전달하고, 배율이 안정되거나 드래그가 끝나면 React 상태에 반영한다. `useMapView`가 카메라 transform과 화면에 보이는 장식만 갱신한다. `PulseCluster`는 memo로 분리하고 제목 줄바꿈·노드 조회 표·선택 연결 정보를 캐시한다.
- 클러스터 제목의 글꼴과 박스 치수는 고정하며, 그룹 transform의 `(zoom / DEFAULT_ZOOM)^0.35 / zoom` 배율로 기존 화면 크기를 유지한다. 블러·여백·모서리도 같은 그룹 안에서 확대·축소한다.
- 문서 라벨은 기준 배율의 글꼴·줄바꿈·말줄임 구조를 유지하고 현재 배율에 맞춰 텍스트 scale을 보정한다. 전체 이름 callout은 이동 중에도 지도 경계 안으로 보정한다.
- 현재 카메라와 화면 크기를 기준으로 140 화면 px의 여유 영역을 둔다. 클러스터 원과 제목이 이 영역 밖이면 `display:none`으로 그리기와 탭 이동에서 제외하고, 다시 들어오면 즉시 복원한다. 모든 클러스터·문서의 데이터와 DOM, 목록과 선택 상태는 유지한다. 전체 활성 이슈 표시 정책은 동일하다.
- 스캔은 노드·간선의 거리를 정렬해 파동과 600ms 잔광 범위의 후보를 찾고, 현재 보이는 클러스터만 갱신한다. 제목은 현재 그룹 배율로 계산한 중심 좌표를 사용한다. 범위를 벗어난 잔광은 한 번 지운다. 카메라·스캔 프레임 처리 안에서는 화면 치수나 `getScreenCTM()`을 다시 읽지 않는다.
- `e2e/pulse-performance.spec.js`는 줌 중 제목 박스 치수 재사용, 화면 밖 클러스터 복귀, 전체 문서 유지, 스캔·제목 중심 일치와 정지를 검증한다. 전후 측정 조건과 결과는 [최적화 기록](../../.impeccable/performance/OPTIMIZATION.md)에 있다.

## 축소 개요와 상세 진입 (WP-153)

이 절은 위의 선택·제목·네온 표시 규칙에 개요 모드를 추가한다. 자동 확대 없이 선택하고 문서 라벨을 모두 표시하는 기존 규칙은 상세 모드에 적용한다.

- 일반·전체화면 모두 `zoom <= 0.45 × 1.2⁵`(약 112%)에서 개요 모드로 전환한다. 직전 64.8% 기준보다 확대 버튼 세 단계 높은 배율이다. 통합 원은 개별 문서 노드와 동일한 배경 그라디언트·주제색 테두리·헤일로·외곽 링을 사용하고 제목을 원 내부에 배치한다. 문서·간선·외부 제목 박스·상세 장식은 숨긴다. 최초 진입과 위치 초기화의 기본 배율은 `1 / 1.2`(약 0.8333)로 유지하므로 개요 모드로 시작한다.
- `clusterOverview.js`는 원 내부 공간과 현재 배율에 맞춰 글꼴과 1~3줄 줄바꿈을 계산하고 넘치는 제목을 `…`로 줄인다. 최소 배율의 화면상 글꼴은 약 14.7px다. 전체 제목은 SVG `title`과 클러스터 버튼의 `aria-label`에 유지한다.
- 개요 원을 클릭하거나 Enter/Space로 활성화하면 현재 위치에서 해당 클러스터의 화면 중앙까지 이동과 확대를 동시에 연속 보간한다. 휠·확대 버튼과 같은 카메라 애니메이션을 공유하며 현재 통합 기준에 0.1을 더한 `1.219744`(약 122%) 배율로 진입한다. 모션 감소 설정에서는 즉시 이동한다. 드래그·초기화는 진행 중 이동을 취소하고, 새 확대 입력은 현재 프레임에서 목표를 갱신한다. 이 동작은 선택 패널을 새로 열지 않으며 기존 선택을 유지한다. 상세 모드에서는 기존 클러스터·문서 선택 동작을 그대로 사용한다.
- `useMapView`가 카메라 프레임마다 개요 여부를 갱신하고 CSS의 `display:none`으로 상세 요소를 그리기와 키보드 포커스 순서에서 함께 제외한다. 상세 요소에 포커스한 채 개요로 전환하면 해당 클러스터 버튼으로 포커스를 옮긴다. 데이터와 DOM은 유지하며 다시 확대하면 상세가 복원된다. 개요에서는 클러스터 중심을 지나는 스캔에 맞춰 통합 원의 헤일로와 외곽 링이 밝아지고 600ms 잔광으로 사라진다. 모드별로 숨긴 요소는 스캔 대상에서 제외하며 일시정지·모션 감소·화면 밖 중단 시 잔광을 지운다.
- 통합 원 글로우 후속 검증: mock 기반 관련 테스트 9개와 lint·build가 통과했다. 데스크톱·모바일에서 이동·축소 후 파동과 통합 원의 화면 좌표, 헤일로·링 투명도, 일시정지·모션 감소 시 잔광 제거를 검증했다.
- 검증: mock 데이터로 lint·build와 Playwright 22회 실행(고유 20개 케이스, 개요 데스크톱·모바일 각 2회)이 통과했다. `e2e/pulse-overview.spec.js`와 `e2e/pulse-zoom.spec.js`가 개요 전환·상세 복귀·확대 범위 등을 다룬다. 실제 Spring/PostgreSQL/AI 연동 검증은 아니다.
- 리뷰 판정은 이 기능 범위에서 반영 가능이다. 최소 배율에서는 작은 원의 제목이 많이 축약되는 점을 후속 가독성 개선 사항으로 남긴다. 전체 제목 접근과 상세 확대 경로는 유지한다.

## 개요 전환 성능 후속 검증 (2026-09-21)

- 카메라가 멈출 때 모든 `PulseCluster`에 새 camera props를 전달하던 경로를 제거했다. React는 기준 텍스트 구조를 유지하고 `useMapView`가 현재 배율을 반영한다.
- 개요 모드에서 숨겨진 상세 제목·문서 라벨·callout의 카메라 갱신을 생략한다. 상세 진입 때 현재 배율로 복원하며, 모드와 가시 클러스터 수 속성은 값이 바뀔 때만 쓴다.
- 통합 원 제목은 고정 18 단위 글꼴을 scale로 보정한다. 줄바꿈 내용과 줄 위치는 달라질 때만 갱신한다. 제목 크기·통합 임계값·클릭 확대·글로우 정책은 유지한다.
- Chromium headless/Vite mock, 1440×900 및 390×900, 1.0↔1.2 확대·축소 6회 왕복을 동일 스크립트로 측정했다. 데스크톱 ScriptDuration 1.783→0.321초, 모바일 1.486→0.308초, 최장 프레임 간격 각각 216.6→116.6ms, 216.6→100.1ms였다. 모드 속성 쓰기는 287/320회에서 실제 전환 12회로 줄었다.
- 레이아웃 비용은 약 4.5~4.7초로 남으며, 모든 프레임의 60fps를 보장하지 않는다. 단일 로컬 반복 측정이고 모바일은 viewport 모사이며 실기기·실제 Spring/PostgreSQL/AI 연동 결과가 아니다.
- 관련 Playwright 8개(개요·애니메이션·스캔·숨겨진 상세 갱신 방지·화면 밖 복원), lint, build 통과. 측정 원본은 로컬 `.impeccable/review/transition-before.json`, `transition-after.json`에 기록했다.

## HTTP 계약

기계 판독 정본: [Pulse OpenAPI 3.0.3](../../frontend/docs/pulse-openapi.json). 현재 8개 GET을 정의한 [통합 OpenAPI](../../frontend/docs/openapi.yaml)와 공통 스키마가 같아야 한다. 프론트의 이전 `/events`·`/entities` 요청은 제거했다.

| 요청                                             | 응답                                                                                  |
| ------------------------------------------------ | ------------------------------------------------------------------------------------- |
| `GET /api/v1/issues/snapshots?from=&to=&source=` | `{data:[{snapshotTs,source,clusterCount}]}`. 출처+시각은 유일. 완료된 0개 스냅샷 포함 |
| `GET /api/v1/issues/map?snapshotTs=&source=`     | `{data:{clusters:[...]},meta:{...}}`. 단일 스냅샷 일괄 그래프, 상세 N+1 요청 없음     |

| 객체     | 필드                                                                                                                                                                    |
| -------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Cluster  | `id`, nullable `issueKey`, nullable `label`, nullable `summary`, `category`, nullable `firstDetectedAt`, `hot`, `pulseScore`, `status`, `memberCount`, `nodes`, `edges` |
| Node     | `pageId`, `wiki`, `title`, nullable·선택 `titleKo`, `isSeed`, nullable `editCount/views/editBaseline/viewBaseline/spikeScore/sizeScore`, `completeness`, `windowStart`, `windowEnd`              |
| Edge     | `id`, `sourcePageId`, `targetPageId`, `kind` (`clickstream/wikidata`), `directed`, `weight`, `evidence`                                                                 |
| Evidence | `label`, Clickstream의 `month` (`YYYY-MM`) 또는 Wikidata의 `observedAt` (UTC)                                                                                           |
| Meta     | 실제 `snapshotTs`, `source` (`live/replay`), 선택적 `dataMode`, `scoreVersion`, `newWindowHours`, 전체 `clusterCount/nodeCount/edgeCount`, `truncated`                  |

지도 ID는 전송 시 문자열이다. 일반 이슈·멤버 DTO는 숫자 long이므로 안전 정수를 검증하고 화면 경계에서 문자열로 보존한다. API 전체를 문자열로 통일할지는 [협의 사항](API_DECISIONS.md)에 남겼다. `nodeCount`는 클러스터별 문서 인스턴스 합계다. `truncated=false`이면 개수는 응답 배열과 정확히 일치한다. true일 때 전체 개수는 반환 개수 이상이며 화면에 일부 반환을 안내한다.

`completeness`는 `complete/pending/unavailable`이다. 수치 null을 0으로 보완하지 않는다. 노드 집계 구간은 시작 < 종료 <= 스냅샷이어야 한다. `DISCARDED`는 반환하지 않는다. 중복 노드·간선, 존재하지 않는 양 끝, 미래 지표·근거, 요청과 다른 시점은 전체 응답 오류로 처리한다. 없는 시점은 404이고 현재 데이터로 대체하지 않는다. 고립 노드는 유효하다.

시간 추적·문서 지표·간선·완료 스냅샷의 스키마와 저장 구현은 존재한다. null이 남은 기존 행, metric 집계 기간, 일부 실패 데이터와 source 배선의 실제 실행 상태는 별도 확인해야 한다. ~~일반 상세 members 수치는 시점 범위가 없는 최신 조회~~ → **해당 `cluster_id`의 고정 `cluster_member` 수치를 읽도록 구현 완료**했다(2026-09-18, WP-129). 지도와 상세가 같은 고정 수치·`completeness`를 읽는 로컬 회귀 테스트는 통과했지만, 같은 canary 실데이터 재실행과 EC2 검증은 하지 않았다.

## Fixture와 검증

2026-09-10에 시연 데이터를 2025-09-01~2026-09-10의 375개 일별 스냅샷으로 확장했다. 슬라이더는 출처가 같은 전체 기간을 탐색한다. 실제 Wikipedia 문서의 합성 지표로 월별 에피소드를 구성하고 내부 fixture의 `~YYYY-MM-DD`로 과거 일별 리포트를 고정한다. raw mock은 이를 안정적인 숫자 ID로 매핑해 지도와 상세를 연결하고 예전 slug도 받는다. 과거 상세의 종목 연결도 현재 Nasdaq-100 고정 목록 안에서 제공하며 그 시점에 오늘의 주가는 넣지 않는다. 출처·생성 규칙·합성 범위·운영 파이프라인과의 차이는 [MOCK_HISTORY.md](./MOCK_HISTORY.md)를 따른다. 이 ID/점수 규칙은 운영 서버 규칙이 아니다. 빈 결과·미제공 지표 처리는 별도 계약과 테스트로 유지한다.

`npm.cmd run test:contract`는 현재 8개 GET DTO와 Pulse OpenAPI 및 모든 스냅샷·부하 fixture를 검증한다. `test:data`는 날짜 경계·관계 무결성·요청 취소·위치 안정성, Playwright는 시간 이동·선택·화면·API 응답 경합·오류 복구를 검사한다. `makeStressMap()`은 20개 클러스터·500개 노드·1,000개 간선이다. 실행 결과는 [검증 기록](../../frontend/docs/VALIDATION.md)에 구분해 기록한다.
