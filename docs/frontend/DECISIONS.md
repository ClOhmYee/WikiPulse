# 온보딩 디자인·제품 결정

## 1. 목적과 범위

### 확정

- 첫 방문에서 WikiPulse가 **흩어진 문서 신호를 추적하고, 관련 신호를 사건으로 묶고, 향후 관련 종목과 연결하려는 서비스**임을 설명한다.
- 1차 사용자는 팀 프로젝트 평가자다. 상세 기능 안내보다 서비스의 차별화된 처리 흐름과 기억에 남는 시각 경험을 우선한다.
- 온보딩은 가입을 요구하지 않는다. 현재는 상시 `탐색 시작하기`와 마지막 장면 CTA로 Pulse Map에 진입한다. 초기 온보딩 전용 범위에서 서비스 탐색으로 확장된 결정이다.
- 온보딩의 주식 그래프는 제품 방향을 보여주는 개념 표현이다. 실제 화면은 mock에서 합성 관계, API에서 서버가 제공한 연결 근거를 표시한다. 서버 실행·AI 품질의 확인 범위는 [API 협의 사항](API_DECISIONS.md)을 따른다.

## 2. 장면 내러티브와 확정 카피

| 장면 | 역할                                  | 제목·부제                              | 설명                                                                            |
| ---- | ------------------------------------- | -------------------------------------- | ------------------------------------------------------------------------------- |
| 01   | 흩어진 문서 변화와 서비스 정체성 제시 | `WIKIPULSE` / `Track. Cluster. Match.` | `Issue-tracking intelligence for matching emerging events with relevant stocks` |
| 02   | 이상 활동 포착                        | `Track.`                               | `Detect unusual activity as it emerges`                                         |
| 03   | 관련 신호의 사건 군집화               | `Cluster.`                             | `Turn related signals into emerging events`                                     |

첫 장면의 스크롤 안내는 `SCROLL TO TRACE`다. 모든 설명은 문장 첫 글자를 대문자로 유지한다.

## 3. 비주얼 방향

### 확정

- 전체 분위기는 검은 우주가 아니라 **near-black cosmic slate**다. 순수 검정보다 청록 기가 도는 깊은 배경으로 정보 그래프의 인상을 유지한다.
- 화면 우측 상단에는 채도가 높은 cyan-teal 광원을 두고, 중앙은 절제된 청록 구름, 가장자리는 비네트로 눌러 깊이를 만든다.
- 의미 노드는 paper white를 기본으로 하고, 일반 지식 연결은 teal, 이상·증거·주식 가격선은 restrained gold를 사용한다.
- 브랜드 문맥에서만 cyan → blue → violet 스펙트럼을 제한적으로 사용한다. 첫 장면 부제의 마침표는 각각 cyan, violet, gold다.
- 카드, 대시보드 패널, 그래프 축, 툴팁 같은 제품 UI는 넣지 않는다. 하나의 살아 있는 점 군집이 전체 설명을 수행한다.
- F+ 첫 화면의 점 레이어와 입체 반응을 주요 레퍼런스로 삼되, 에셋을 복제하지 않고 WikiPulse의 색·카피·장면 서사로 재구성한다.

## 4. 장면별 시각 결정

### 01 — Scattered changes

- 우측에 350개 흰색 의미 노드가 입체 구를 이룬다.
- 중심부의 가까운 노드만 얇은 흰색 간선으로 연결한다.
- 포인터는 군집 전체를 회전시키지만 노드가 커서를 피해 달아나지 않는다.
- 왼쪽 아래에는 아이콘과 CSS 워드마크, 부제, 설명, 스크롤 안내를 배치한다. 부제 이하의 텍스트는 워드마크 `W`의 시작축에 정렬한다.

### 02 — Track

- 1→2 전환에서 군집을 오른쪽으로 옮기지 않는다.
- 같은 3D 구가 방사·접선·깊이 방향으로 퍼졌다가 회전된 구로 다시 모이며 확대되는 느낌을 만든다.
- 간선은 제거한다.
- 다음 장면의 클러스터 소유 노드 중 38개만 같은 위상으로 `0.7s`마다 흰색 글로우를 낸다.
- 글로우하지 않는 112개도 클러스터 소유권과 3장면 이동은 그대로 유지한다.
- 포인터 반응은 회전만 남기고 국소 반발은 사용하지 않는다.

### 03 — Cluster

- 첫 150개 노드가 유기적인 사건 군집을 형성한다.
- 일반 군집은 teal, 이상 신호는 gold, 일부 강조점은 paper white다.
- 사용하지 않는 200개 노드는 사라지지 않고 주변의 희미한 3D 점으로 남는다.
- 이 주변 노드들은 4장면에서 새로 생성되지 않고 바로 주식 그래프의 가격·거래량 노드로 이동한다.

### 04 — Match

- 데스크톱에서 시각 구성은 화면 우측 약 2/3를 사용한다.
- 사건 클러스터와 추상 주식 그래프를 좌우로 두되, 폭을 억지로 맞춰 납작하게 만들지 않는다.
- 클러스터는 장면 3의 동일한 150개 노드를 유지한다.
- 나머지 200개 가운데 140개가 가격선, 60개가 거래량 필드가 된다.
- 다섯 개의 매핑 선은 클러스터의 출발점과 가격선의 도착점을 세로 방향으로 분산시켜 한곳에 몰리지 않게 한다.
- 가격 노드의 이동은 즉시 시작하지만 gold 색상 전환은 장면 진행률 `0.68`부터 시작한다. 가격 간선은 `0.58`, 매핑 선은 `0.78` 이후 나타난다.
- 모바일에서는 클러스터를 위, `3.3` world-unit 폭의 차트를 아래에 둔다.

## 5. 배경 점과 공간감

- 의미 노드와 별개로 950개의 데스크톱 배경별을 사용한다. 700px 미만에서는 560개다.
- 깊이에 따라 원근 분포를 만들고 gold, teal, white를 거의 같은 비율로 섞는다.
- 초기 z가 0보다 작은 먼 점 그룹은 `0.06`, 나머지는 `0.054` world-unit 크기로 두 번 그린다.
- 스크롤 방향과 속도에 따라 y축 회전 방향과 속도가 달라진다.
- 최종 버전에는 혜성 꼬리, 잔상, 고스트 레이어가 없다. 점의 원형 실루엣과 회전만으로 속도를 전달한다.

## 6. 입력과 전환

- 연속 스크롤 실험 후 최종적으로 **장면 단위 스냅 이동**을 선택했다.
- 한 번의 수직 휠 또는 스와이프는 인접 장면 하나만 이동한다.
- 장면 이동 자체는 약 1.9초 동안 잠겨 연속 입력으로 여러 장면이 건너뛰지 않게 한다.
- 노드와 카피는 목표 장면으로 즉시 교체되지 않고 연속 progress를 따라 보간한다.
- 카피는 DOM에 계속 마운트한 채 수직 이동, 블러, 크로스페이드로 전환한다.
- `prefers-reduced-motion`에서는 장면 앵커로 즉시 이동하고 공간 보간·별 회전·포인터 회전을 멈춘다.

## 7. 반응형·접근성 결정

- 데스크톱에는 왼쪽 장면 레일, 모바일에는 이전·다음 원형 버튼을 제공한다.
- 키보드는 `ArrowUp/Down`, `PageUp/Down`, `Space`, `Shift+Space`, `Home`, `End`를 지원한다.
- 텍스트는 실제 DOM으로 유지하고, 장식용 WebGL 필드는 보조 기술에서 숨긴다.
- 첫 장면 설명은 721px 이상에서 한 줄, 작은 화면에서는 줄바꿈을 허용한다.
- 2–4장면 제목의 x/y 원점은 첫 장면 워드마크 `W`의 실제 렌더링 위치를 기준으로 맞춘다.
- WebGL을 사용할 수 없거나 컨텍스트가 손실되면 읽을 수 있는 정적 DOM 버전으로 전환한다.

## 9. 변경 시 지켜야 할 불변 조건

1. 350개 의미 노드는 장면 사이에서 교체되지 않는다.
2. 클러스터·이상 신호·가격·거래량 소유 인덱스는 전환 중에도 유지한다.
3. 글로우 표시 여부와 다음 장면의 클러스터 소유권을 분리한다.
4. 색상 지연이 필요한 경우 위치 progress와 색 progress를 분리한다.
5. 배경별은 의미 데이터가 아니며 이벤트·주식 노드로 재사용하지 않는다.
6. Match 장면은 향후 연결 개념이며 실제 매칭 성능을 암시하지 않는다.
