# PulseMap 확대·축소 최적화

2026-09-17에 측정한 펄스맵 성능 검증 결과입니다.

## 변경

- 카메라 보간 중 React 전체 지도 렌더를 제거하고 ref와 구독자로 프레임을 전달했습니다.
- 클러스터를 memo 컴포넌트로 분리하고 제목 치수를 고정해 transform으로 확대했습니다.
- 화면 밖 클러스터의 렌더링과 스캔 갱신을 중단하고 재진입 시 복원했습니다.
- 스캔 대상의 거리를 정렬해 파동과 잔광 범위를 이진 탐색했습니다.
- 카메라·스캔 프레임의 반복 DOM 측정과 중복 getScreenCTM 호출을 줄였습니다.

## 당시 측정

production mock, headless Chromium 1440×1000 전체화면, 클러스터 36개·노드 318개·간선 282개, 휠 입력 24회, CPU 추가 제한 없음, 각 2회 평균입니다.

| 항목 | 수정 전 | 수정 후 |
| --- | ---: | ---: |
| rAF 처리 빈도 | 29.56 fps | 44.71 fps |
| p95 프레임 간격 | 50.05 ms | 33.40 ms |
| 입력 시나리오 소요 시간 | 5.62초 | 4.26초 |
| Script 시간 | 0.703초 | 0.072초 |
| Style 계산 시간 | 0.522초 | 0.123초 |
| Layout 시간 | 2.558초 | 2.755초 |
| 전체 Task 시간 | 5.460초 | 3.883초 |

rAF 빈도는 약 51% 높아졌지만 Layout 누적 시간은 감소하지 않았습니다. 처리한 프레임 수와 프레임당 배치 비용을 구분해야 하며, 이 값을 실제 표시 FPS나 모든 사용자 기기의 성능 보장으로 해석하지 않습니다.

4× CPU 감속 결과는 편차가 커 일정한 개선율이나 60fps 달성을 주장하지 않습니다. 추가 라벨 최적화 실험도 차이가 작아 제품 코드에 적용하지 않았습니다.

당시 최종 통합 검증에는 전체 E2E 43개, API 계약 E2E 13개 통과 기록이 있습니다. API 계약 테스트는 HTTP 응답 가로채기 검사로 Spring·DB 통합 검증과 구분합니다.

관련 구현은 [펄스맵 계약](PULSE_MAP.md), [디자인](../design/pulse-map/DESIGN.md)과 함께 확인할 수 있습니다.
