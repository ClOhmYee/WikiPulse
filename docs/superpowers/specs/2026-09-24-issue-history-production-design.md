# 운영 이슈 탐색의 대표 문서·리포트 달력 통합

기준: 2026-09-24 `origin/develop` `3099ea0`. 기존 로컬 미리보기 검증 결과를 운영 API 기반 화면에 옮기되 이 작업에서 배포하지 않는다.

## 목적과 선택

- `/issues`는 현재 페이지 20건이 아니라 완료된 전체 스냅샷의 대표 문서를 `source + issue_key`별 한 건으로 보여준다. 검색·상태 필터·페이지네이션은 서버에서 한다. NULL 키는 ID별 독립 행이다.
- `/issues/{id}`에는 한국 시간 기준 달력을 추가한다. `issue_report` 행이 있는 시점만 활성화하고, 선택 시 **기존** `GET /issues/{id}`가 돌려준 그 시점의 요약·섹션형 본문·멤버·종목을 보여준다. 요약만 저장된 행도 선택 가능하다. 리포트가 없으면 선택 가능한 날짜가 없다.
- `issue_key`는 동일한 대표 문서의 기록을 잇는 키이지 현실의 동일 사건 ID가 아니다. UI는 이를 명시한다.
- 기존 피드/상세/펄스맵 계약을 바꾸지 않는다. 최신 스냅샷용 `/issues`를 전체 이력용으로 재정의하면 다른 소비자가 깨지므로 읽기 전용 API 두 개를 추가한다. DB 스키마·적재·요약 생성은 변경하지 않는다.
- `VITE_ISSUE_HISTORY_ENABLED=true`와 API 데이터 모드일 때만 새 화면을 사용한다. 기본값은 꺼짐이다. Vite 플래그는 빌드 시점 값이다.

## API

1. `GET /api/v1/issues/history/groups?q=&status=&source=&offset=&limit=`. `q`는 선택 사항이며 대표 행의 label 부분검색이다. 응답은 대표 최신 ID/label/source/status/score/snapshotTs, 처음 시각, 전체 발생 횟수, 해당 대표 문서의 최신 리포트 ID, 최신 행의 요약·문서 수·검증된 종목 수를 포함한다. 완료 스냅샷과 비폐기 행만 읽는다. 정렬은 최근 시각 내림차순·ID 오름차순이다. `status`는 최신 행의 상태를 필터링한다. `q`의 `%`, `_`, `\`는 문자 그대로 검색한다. 페이지네이션은 묶음 단위다.
2. `GET /api/v1/issues/{id}/history/reports?offset=&limit=`. 그 ID와 같은 `source + issue_key`에 속한 **리포트 보유** 시점만 `snapshotTs DESC,id DESC`로 반환한다. NULL 키는 기준 ID만 대상이다. 페이지네이션을 제공하고 프론트는 모든 페이지를 읽어 달력을 완성한다. 없는/폐기된 기준 ID는 404다.

두 API는 기존 `ApiResponse` 봉투를 사용한다. `cluster_snapshot(source,snapshot_ts)`가 있는 완료 시점만 선택한다. 기존 `issue_cluster(issue_key,snapshot_ts)` 인덱스를 우선 사용하고 성능 문제 실측 전에는 마이그레이션을 추가하지 않는다.

## 운영 화면과 안전장치

- 기존 `ExplorePage` 스타일·랭킹 영역을 유지하며 새 데이터만 서버 묶음 응답으로 바꾼다. 대표 카드는 최신 리포트가 있으면 그 ID로, 없으면 최신 이슈 ID로 연결한다. 묶음 카드는 단일 이슈 ID 저장 버튼을 표시하지 않는다.
- 상세는 기존 탭과 API를 유지하고 달력만 추가한다. 날짜에 리포트가 여러 개면 시각별 버튼을 표시한다. 날짜를 누르면 해당 ID 주소로 이동한다. 이력 API가 실패해도 기존 상세는 계속 볼 수 있게 한다.
- 기존 모드(플래그 꺼짐), 검색 특수문자, 출처/NULL 키 분리, 같은 날 다중 시점, 리포트 없음, 서버 페이지 경계, API 실패, 기존 상세/펄스맵 회귀를 검증한다.
- 배포는 별도 승인. 새 API 먼저 배포·실제 DB 읽기 전용 확인 후, 켜진 프론트 빌드를 배포한다. 이상 시 이전 프론트 빌드로 돌린다. 데이터 변경이 없으므로 DB 롤백은 없다.
