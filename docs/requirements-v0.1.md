## 1. 개요

**한 줄 소개**: 위키피디아 실시간 이슈를 포착해, 연관된 미국 상장 종목과 함께 보여주는 투자 정보 서비스

**배경**: 위키피디아 실시간 수정 이력 기반 트렌드 분석 아이디어에 투자 정보 제공이라는 축을 더해 재구성. 시장(미국 증시 한정), 데이터 파이프라인, 알고리즘 매핑을 확정한 v0.1 단계.

## 2. 타겟 사용자

실제 주식 시세·흐름의 원인을 뉴스(이슈)로 파악하고 싶은 사람. 종목을 먼저 검색해서 정보를 찾기보다, 지금 화제인 이슈를 먼저 보고 그것이 시장에 미치는 영향을 확인하고 싶어하는 사용자.

## 3. 서비스 설명 / 주요 기능

위키피디아 편집 활동에서 실시간으로 급증 신호를 포착하고, 노이즈가 아닌 실제 화제성 이슈인지 검증한 뒤, 연관된 미국 상장 종목을 자동 매칭해 이슈 피드로 제공한다. 메인 화면은 이슈 피드, 상세 페이지에서 연관 종목의 주가 흐름과 근거를 제공한다.

**주요 기능**

- 실시간 이슈 피드 — 위키피디아 편집 급증 기반 트렌딩 이슈 노출
- 이슈 중요도 검증 — 봇 편집·사소한 수정 등 노이즈 필터링
- 이슈-종목 매칭 — 연관된 미국 상장 종목 자동 연결
- 종목 상세 뷰 — 주가 그래프 + 이슈 발생 시점 표시 + 연관 근거(상관관계·유사도) 제공
- 과거 유사 이슈 사례 제공
- 이슈 유형 자동 분류(정치/경제/산업 등)
- 관심종목 필터링

## 4. 시스템 아키텍처

### 4.1 메인 파이프라인 (실시간)

```
Wikipedia EventStreams (전체 편집 이벤트)
  → Kafka (상시 가동, 전체 스트림 수집)
  → Spark Structured Streaming (윈도우 집계로 편집 급증 실시간 감지)
  → 급증 후보 발생 시 즉시 트리거:
       Hadoop MapReduce 잡 실행
         - 이슈 검증 (LLM + web_search)
         - Equi-Join (이슈-종목 매핑)
         - 벡터유사도/KNN (관련 종목 랭킹)
       (레이어B: 동일 로직 Spark로 재구현, 성능 비교)
  → 검증·매칭 끝난 이슈 → 이슈 피드에 실시간 반영
```

관심종목 알림은 별도 파이프라인 없이, 메인 파이프라인 결과를 사용자 관심사로 필터링해 커버한다.

### 4.2 상세 페이지 (배치)

```
종목 주가 그래프 + 상관분석 (행렬곱, 일단위 배치)
  → 이슈 발생 시점 전후 주가 변동 시각화
과거 유사 이슈 사례 (셋 유사도, 자카드)
이슈 유형 클러스터링 (K-Means)
```

## 5. 필수 알고리즘 매핑 (레이어 A)

| 알고리즘 | 서비스 내 역할 |
| --- | --- |
| 역색인 | 위키 아티클 본문/제목 검색, 기업명↔아티클 매핑 보조 |
| 행렬합·행렬곱 (1P/2P/스트리밍) | 주가 급변 구간 × 위키 편집량 시차상관행렬 계산 |
| Equi-Join (All-Pair/Repartition) | 위키 아티클 ↔ 기업/종목 매핑, 종목 후보 1차 필터링 |
| 벡터 유사도 셀프조인/Top-K | 급변 구간 패턴 ↔ 이슈 활동 패턴 비교, 원인 후보 Top-K |
| K-Means | 이슈 유형 클러스터링(실적발표형/지정학형/산업이슈형 등) |
| 셋 유사도 셀프조인 (자카드) | 과거 유사 이슈 사례 탐지 |
| KNN조인 | 급변 이벤트 ↔ 이슈 벡터 매칭, 원인 후보 랭킹 구현체 |

## 6. 데이터 소스

| 구분 | 소스 | 비고 |
| --- | --- | --- |
| 이슈 신호 | Wikipedia EventStreams, Pageviews API | 편집 이벤트(실시간) + 조회수(시간단위 배치, 보조 신호) |
| 엔티티 매핑 | Wikidata SPARQL | 기업 위키 아티클 ↔ 티커·산업 분류 속성 |
| 주가 | yfinance(메인), Alpha Vantage(보조/검증) | 미장 한정, 무료 |
| 재무제표 | SEC EDGAR (data.sec.gov) | 공식 XBRL API, 무료·API키 불필요 |

⚠️ 국장(한국투자증권 API)은 약관상 "시세정보 제3자 제공 불가" 조항 리스크로 제외. IEX Cloud는 2024년 8월 완전 종료되어 후보에서 제외.

| 구분 | 스택 |

ℹ️ 프론트/백엔드 프레임워크는 명시적으로 확정된 바 없어 팀 구성과 프로젝트 커리큘럼 기준 추천안임. 팀 논의 후 변경 가능.

## 8. AI(LLM) 활용 원칙

- **이슈 중요도 검증**: 감지된 급증 후보를 Claude + web_search로 실제 뉴스와 교차검증, 노이즈(봇 편집 등) 필터링
- **결과 자연어화**: 알고리즘이 산출한 정량 결과(상관계수, 유사도 점수)를 사용자용 설명 문장으로 변환
- **비용 원칙**: 두 지점 모두 "감지된 이슈 후보 수"에 비례하는 호출이며, 사용자 요청마다 실시간으로 호출되지 않음 → 서비스 규모(사용자 수)와 무관하게 비용 고정
- **개발 단계 검증**: 파이프라인 구현 전 "개념→관련 종목" 추론 타당성을 `test/concept-to-stock-poc`에서 LLM 프로토타입으로 사전 테스트 완료 (프로덕션 코드 아님)

## 9. 포지셔닝 / 주의사항

🚫 "위키피디아 활동과 주가 변동의 상관관계"는 학술 연구가 존재하나 결과가 엇갈림(일부 연구는 상관관계 없음으로 결론). **"정확한 원인 규명"이 아니라 "참고할 만한 후보 컨텍스트 제공"으로 서비스 문구·톤을 겸손하게 유지할 것.** 투자 조언이 아니라는 면책 문구 배치 필요(법적 검토 필요 항목, 10번 참고).
